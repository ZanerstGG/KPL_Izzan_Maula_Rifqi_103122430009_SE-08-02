## Soal
Diberikan dua kode yang sama-sama melakukan operasi pembagian. Pertama menggunakan asersi, kedua menggunakan eksepsi.
```
const assert = require('assert');

function divide(a, b) {
  assert(typeof a === 'number' && typeof b === 'number', 'Nilai harus bilangan bulat');

  assert(b !== 0, 'Tidak bisa pembagian dengan nol');

  return a / b;
}
```
```
function divide(a, b) {
  if (typeof a !== "number" || typeof b !== "number") {
    throw new TypeError("Nilai harus bilangan bulat");
  }

  if (b === 0) {
    throw new Error("Tidak bisa pembagian dengan nol");
  }

  return a / b;
}

try {
  const result = divide(10, 2);
  console.log("Hasilnya adalah:", result);
} catch (error) {
  console.error("Error:", error);
}
```
Menurutmu, kapankah kita saatnya menggunakan asersi atau eksepsi untuk fungsi seperti ini di atas? Apakah kita harus sepenuhnya asersi, atau sepenuhnya eksepsi? Lakukan riset dan berikan jawabannya dalam bentuk esai minimal 300 kata.
## Deskripsi
Dalam Software Engineering, membuat code yang tidak akan mengalami kesalahan atau error itu sangat hampir mustahil. Namun, dengan menerapkan defensive programming, sangat memungkinkan meminimalisir dampak dari kesalahan tersebut dan menjaga sistem tetap stabil. Dua ide pemograman yang sering digunakan programmer untuk melindungi program adalah assertion dan exception. Melihat dua contoh kode operasi pembagian pada kasus di atas, muncul pertanyaan, kira-kira kapan saatnya  menggunakan asersi, kapan menggunakan eksepsi, dan apakah harus memilih salah satu saja secara mutlak? <br>
Asersi pada dasarnya adalah alat bantu bagi developer selama fase development program. Asersi berfungsi sebagai bentuk penerapan Design by Contract, yaitu menetapkan aturan mutlak yang tidak boleh dilanggar oleh aliran kode. Jika sebuah asersi gagal seperti kondisi bernilai false, itu berarti ada bug yang dibuat oleh programmer, bukan kesalahan dari pengguna. Dalam contoh fungsi `divide(a, b)`, asersi `assert(typeof a === 'number')` digunakan untuk memastikan bahwa tidak ada bagian lain dari sistem internal yang secara tidak sengaja mengirimkan data berupa teks ke dalam function divide ini. Asersi sangat bagus untuk menemukan masalah secepat mungkin sebelum program dipublish. Di sisi lain, eksepsi dirancang untuk menangani masalah yang terjadi saat program sudah berjalan dan digunakan oleh user. Berbeda dengan asersi yang secara tegas mengindikasikan bug internal dari programmer, eksepsi digunakan untuk menangani situasi tidak terduga yang berasal dari luar control dari program. Contohnya adalah input formulir user yang salah, koneksi internet yang buruk, atau memorinya penuh. Dengan menggunakan pola `throw new Error` dan menangkapnya dengan `try...catch`, program tidak akan langsung crash. Sebaliknya, program bisa memulihkan diri dan memberikan message kepada pengguna. <br>
Lalu, apakah harus menggunakan sepenuhnya asersi atau sepenuhnya eksepsi? Jawabannya adalah tidak perlu, karena keduanya tidak dibuat untuk saling menggantikan, melainkan untuk saling melengkapi satu sama lain. Menggunakan salah satu secara eksklusif akan merugikan pengembangan sistem. Jika hanya menggunakan asersi hingga ke tahap produksi, program akan mati saat menghadapi input user yang salah, sehingga menghasilkan user experience yang sangat buruk. Sebaliknya, jika hanya menggunakan `try...catch` untuk setiap pengecekan tipe data internal, kode akan menjadi sangat lambat, sulit dibaca, dan menyembunyikan bug yang seharusnya segera diperbaiki. <br>
Kesimpulannya adalah, Penulisan kode yang paling bagus adalah menggunakan keduanya sesuai dengan konteksnya masing-masing. Menggunakan asersi selama fase development untuk membasmi bug dan memastikan struktur data internal tetap konsisten. Kemudian, gunakan eksepsi di bagian luar program yang berinteraksi langsung dengan ketidakpastian user seperti input user, API, atau koneksi yang bermasalah untuk meminimalisir program mengalami kegagalan.
