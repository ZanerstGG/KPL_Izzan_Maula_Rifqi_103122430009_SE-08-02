## Deskripsi
Singleton pattern pada frontend/src/lib/auth-client.ts

```
import 'dotenv/config';
import { createAuthClient } from 'better-auth/react'

export const authClient = createAuthClient({
  baseURL: process.env.NEXT_PUBLIC_BETTER_AUTH_URL,
  basePath: '/api/v1/auth',
})
```

Di frontend, kami perlu menginisialisasi pustaka Better Auth agar bisa terhubung dengan backend. Pemanggilan fungsi inisialisasi ini menggunakan pola Singleton berbasis ES Modules, Karena:
1. Pemanggilan createAuthClient hanya dieksekusi satu kali ketika modul ini pertama kali dibaca oleh sistem.

2. Saat komponen atau halaman manapun di antarmuka (UI) kami memanggil import { authClient } from '@/lib/auth-client', Node.js/Bundler (seperti Webpack/Turbopack di Next.js) akan melakukan caching. Mereka semua akan menggunakan instance authClient yang sama di dalam memori.

3. Jika kami tidak mengekspor variabel ini sebagai Singleton dan sebaliknya menginisialisasi klien baru di setiap file komponen antarmuka, aplikasi akan mengalami pemborosan memori dan kemungkinan terjadi tumpang-tindih session/cookies otentikasi.
